# 项目生命周期交付说明

本轮从现有系统续建，所有写入继续使用原 API、服务端权限与财务事务；不修改数据库 Schema，不迁移、不清空任何数据。Sites D1/R2 与本机 SQLite/附件适配器均保留。

## 日常操作

1. 工作台查看已确认应收、有效实收、未收余额、逾期余额、红色风险项目及本月到期未回款。
2. 在待办队列点击项目对应的操作，直接进入该项目及付款节点。
3. 项目顶部查看金额、风险、当前状态与下一步；合同、节点、催收、回款和审计使用同页标签。
4. 新建项目后直接进入付款节点区。新增节点、回款、催缴及作废更正在右侧面板中操作，项目上下文保持不变。
5. 提交后重新加载服务器数据。金额、风险、有效流水、自动核销和归档结果同时更新。

## 导航与兼容性

- 工作台：经营指标、优先任务、项目状态总览。
- 项目：进行中项目、历史财务归档项目。
- 数据中心：原应收、回款、催缴、审计查询，以及按项目聚合的风险分析。
- 系统管理：原 Excel 导入、风险规则及当前账号权限说明。

旧的 `#receivables`、`#receipts` 等链接继续可用。项目链接形式为 `#projects/{内部ID}/{工作区}?node={应收ID}`；每次都从当前账号可见的最新 bootstrap 中解析，项目或节点不可用时不会回退到其他对象。

## 展示口径

- 生命周期是派生读模型，不是新的持久化业务状态。逾期优先显示，待确认、催收和部分回款信号可并存。筛选计数不能相加。
- 已形成应收包括待确认节点；首页财务指标仅统计已确认节点。作废回款不计入实收。
- 本月预计回款指上海时区本月到期且目前未收的余额，包含本月逾期，排除前月欠款；不是实际到账预测或付款承诺。
- 30 天无有效跟进是工作提醒，不改动现行风险规则，也不代表没有线下联系。
- 催收不是回款前置步骤；有效回款自动核销，不新增“待人工核销”流程。
- 已结清指已形成应收结清；财务归档不表示合同履行完毕。新增节点或回款更正仍会依原规则恢复进行中。
- 已形成金额超过合同总额时展示差额，保留原值，不裁剪或擅自拦截原有数据。
- 处理权限标签不是人员分派。实际操作人来自原始记录；确认时间缺失时明确说明，不根据审计缺失推断未确认。
- 项目审计来自现有接口最近 300 条可见日志，不宣称完整项目历史。所有原始日志继续保存。

## 实现边界

新增纯函数、导航及组合 UI；原表单、验证与写接口复用。bootstrap 仅额外带出已有的 `confirmed_at`、`updated_at` 和上海业务日期，字段为可选，兼容旧服务响应，不需要迁移。未实现新账号管理界面，仍使用已有本机账号管理工具。

## 验证

保留全部原测试，增加生命周期状态、金额口径、提醒边界、跨项目上下文、链接解析、审计关联和实际组件服务端渲染测试。按要求运行 `pnpm run test:unit`、`pnpm run test:integration`、`pnpm run build`；测试使用独立临时数据，不向正式库植入示例。

本机 pnpm 11 会因已有 workspace 元信息过期尝试重装依赖。验证时使用命令级 `pnpm_config_verify_deps_before_run=warn`，仅把自动重装改为警告，保留现有依赖和安全策略；没有执行依赖清理或安装。

界面沿用 frontend-design / frontend-ui-engineering / apple-design 的分层、可访问状态与减少动效原则，采用中性色数据工作区和现有 Base UI 面板。尚未进行浏览器交互式视觉、读屏或手机真机验收，不将编译和组件渲染测试等同于这类验收。

### 本轮验证结果（2026-08-31）

- `test:unit`：26 项通过。
- `test:integration`：21 项通过；D1/R2 重启前后 1013 个测试项目、1017 笔测试应收和 5 份附件一致。
- `test:node`：同一套 21 项回归及 SQLite/文件重启持久化检查通过。
- `test:selfhost`：8 项通过，包括正式登录、CSRF、区县隔离、财务流程、备份恢复。
- `typecheck`、`lint`、`build`、独立前端与 API 生产构建通过。
- 本机和现有公网入口均返回新版 JS/CSS（HTTP 200）；未登录 bootstrap 返回 401。

首次 D1 集成运行曾在超大文件上传的开发代理传输层返回 500；应用处理器未修改，加入诊断及随后移除诊断的两次完整运行均通过，上传正确返回 413。未删除测试、放宽断言或将此暂态问题宣称为已定位修复。

本轮只热更新自托管静态界面，保留旧静态资源供已打开页面使用；没有重启公网隧道或正在运行的 API。新增的可选时间字段已完成 API 构建与测试，下次正常重启生效；当前界面兼容旧 API，缺失确认时间使用已有审计证据或明确显示未提供。正式数据没有改动。

- 改为浅灰侧栏、白色内容区、黑色主操作；蓝色保留给链接和选中指示，红黄绿继续表达风险。
- 工作台使用「待处理 / 项目概览」双标签和连续待办列表；经营指标在桌面右侧、手机上方，口径按需展开。
- 项目页使用「动态 / 款项 / 资料」三组导航。原七个工作区、深链接、权限和表单全部保留，金额与流程依据折叠展示。
- 动态按业务日期倒序，默认最近 12 条，可加载更早记录；后续日程独立展示。没有删除历史、作废记录或修改账务规则。
- 28 项单元测试、21 项 D1/R2 集成测试（含重启持久化）、类型检查、lint 与生产构建通过。隔离演示环境使用 headless Chrome 检查真实 320/768/1024/1440px 视口，无整页横向溢出，并检查工作台标签切换；不等同于读屏和手机真机全面验收。
- 未新增依赖、未修改 API 或数据库；仅更新自托管静态资源，保持运行中的数据库、API 和公网隧道不变。
