# 项目应收管理系统（MVP）

面向市级管理员、区县管理员和区县填报人的中文管理工作台。现在支持前后端分离的电脑自托管：React/Vite 前端、独立 Node.js API、原生 SQLite 数据库、本机附件存储与 HTTPS 隧道。原有 Sites/D1/R2 私有演示版保留作为回退，两套数据库不混用。

## 产品化重构与容器部署

本轮新增紧凑业务工作区、项目快捷检索、前端 services/hooks 分层、兼容的 `/api/v1`、项目/回款服务与仓储分层，以及 Docker/Compose 和检查流水线。既有 API、数据库、权限及财务规则保持兼容。

完整变更、容器启动命令、环境配置、验证结果和未完成事项见 [产品化重构交付记录](docs/PRODUCTIZATION.md)。Docker 镜像与公网部署仍需现场验证；源码构建通过不表示正在运行的正式进程已经升级。切换前先停写、备份，并保留旧构建；不要在服务运行时覆盖其构建目录。

工程边界、目标目录和迁移路线见 [系统架构](docs/architecture/README.md)；关键取舍记录在 [ADR](docs/adr/0001-evolutionary-modular-architecture.md)，健康与故障恢复见 [运维说明](docs/operations/HEALTH_AND_RECOVERY.md)。

## 电脑作为服务器（当前交付方式）

需要 Node.js ≥ 24.11.1。本机已经安装好依赖时：

```bash
npm run selfhost:build
npm run selfhost:init
npm run selfhost:start
```

访问 `http://127.0.0.1:4173/`。初始管理员为 `admin`，随机密码写入命令输出的本机文件（权限 0600、Git 忽略），首次登录必须改密。初始化可重复执行，不覆盖已有账号或业务数据。

### 日常手动启动（当前电脑）

每次重启电脑或服务退出后，在项目目录执行：

```bash
cd '/Users/yinxigao/Documents/ChatGPT/Tele 贷款催收项目'
npm run selfhost:start
```

如果刚修改过前端或后端代码，先重新生成自托管构建：

```bash
npm run selfhost:build
npm run selfhost:start
```

启动命令所在终端需要保持打开；浏览器访问 `http://127.0.0.1:4173/`。停止时在另一个终端执行 `npm run selfhost:stop`。当前电脑没有 `pnpm` 也不影响运行，`npm` 可以直接执行这些项目脚本。

```bash
npm run selfhost:stop
npm run selfhost:public
```

公网启动器输出临时 HTTPS 地址，并保持前端、API 和隧道运行；用 `npm run selfhost:stop` 停止。首次安装隧道工具可执行 `npm run selfhost:tunnel-install`（使用已登录的 GitHub CLI 下载并校验官方程序）。

正式库默认在 `.data/selfhost/receivables.sqlite`，不生成示例项目、应收、回款或催缴；保留区县和风险规则配置。原 `.wrangler/` 演示库和私有站点没有删除或迁移。电脑关闭、休眠或断网时外网无法访问；临时隧道不承诺在线时间，重启后地址可能变化。

架构、账号开通、备份恢复和部署边界见 [自托管交付手册](docs/SELF_HOSTING.md)。

## 已实现范围

- 应收工作台：待确认、剩余应收、部分回款、逾期未留痕等运营指标与明细。
- 项目管理：手工新增、合同附件、付款节点、详情与历史项目。
- 应收管理：待确认应收、市级确认、核销状态、逾期风险和法律风险。
- 回款流水：多笔回款、凭证、超额阻止、作废并追加更正。
- 催缴中心：微信、面谈、正式函件、领导介入、附件与不可覆盖时间线。
- 导入中心：三份 Excel 模板、预览、逐行校验、有效行提交和错误 CSV。
- 审计日志：实体、字段、原值、新值、原因、来源、操作人和操作时间。
- 风险设置：市级管理员调整阈值，规则变更写入审计。
- 服务端角色权限与区县数据隔离。
- 可点击的工作台指标、应收详情及合并时间线、按区县筛选与 CSV 台账导出。
- 回款、更正、核销与审计事务一致；导入预览绑定创建会话及区县，防止重复提交。

## 旧 Sites 演示版运行（不用于自托管公网入口）

前置条件：Node.js ≥ 22.13（验收使用 24.11.1）、pnpm；模板结构测试使用系统 `unzip`。首次取源码执行 `pnpm install --frozen-lockfile`。保留 pnpm 锁文件，不要混用其他安装器重建依赖。

依赖安装后：

```bash
npm run dev -- --host 127.0.0.1 --port 3000
```

这里使用 npm 执行已有脚本，避免某些 pnpm 版本在 `run` 前自动重装依赖；不会生成 npm 锁文件。

浏览器访问：`http://localhost:3000/`

首次访问会幂等创建数据库结构和匿名演示数据；再次启动不会覆盖已有业务数据。

接口集成测试会自动使用一次性的临时 D1/R2 状态目录和空闲端口，结束后清理临时状态，不会向日常演示数据库写入“自动化验收”数据。

## 演示身份

- 市级管理员：查看全市、创建项目、确认应收、调整风险规则及兜底处理。
- 区县管理员：查看本区、维护付款节点、登记及更正回款和催缴、查看本区审计。
- 区县填报人：查看本区、登记回款和催缴、上传附件。

页面右上角可切换角色和碑林、雁塔、莲湖三个匿名区县。HttpOnly Cookie 仅保存随机会话令牌，角色与区县从服务端会话读取；不接受客户端直接声明权限。这是可自由切换身份的演示机制，不等同于正式登录认证。

## 验证

```bash
npm run verify
```

该命令依次进行类型检查、静态检查、单元/真实模板测试、隔离接口测试、重启持久化验证和生产构建；任一步失败立即停止。也可单独运行 `npm run test:unit`、`npm run test:integration`、`npm run build`。

- 单元测试覆盖日期、金额、核销、逾期风险、法律风险、项目归档和权限矩阵。
- 接口测试覆盖跨区拒绝、完整链路、并发回款/更正、审计失败回滚、导入归属与重放、三类各 1000 行导入。
- 重启测试比对业务记录、会话及附件 SHA-256；只清理脚本自己创建的临时目录。
- `npm run db:generate` 应显示 14 张表且无未生成的结构变更；新增 3 张自托管认证表，业务表和金额口径保持不变。
- 测试会主动制造两个数据库错误以验证事务回滚，相应 500 日志是预期结果；以最终测试汇总为准。

三份 `.xlsx` 模板已包含填写说明、冻结首行、日期/金额格式和 1000 行校验。可选维护脚本：`python3 scripts/prepare-templates.py`（需要 openpyxl；应用运行不需要 Python）。

## 一期边界

自托管版包含密码账号、会话过期、退出、强制初始改密、服务端区县权限及请求来源/CSRF 校验。不包含企业单点登录、交付模块、领导大屏、CRM/计费接口、AI 合同解析、历史数据迁移和生产级安全/高可用承诺。旧 Sites 部署仍保持仅所有者可访问，演示身份不能用于开放公网。
