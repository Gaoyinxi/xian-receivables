# 一期 MVP 交付手册

交付日期：2026-08-31。适用范围：匿名数据的内部演示、业务流程验证和后续开发交接。此版本不是面向真实财务数据的正式生产上线认证。

## 入口与源码

- 应用：[项目应收管理系统](https://xian-receivables.yinxigao.chatgpt.site)，保持仅所有者访问，不扩大分享权限。
- 源码：[Gaoyinxi/xian-receivables](https://github.com/Gaoyinxi/xian-receivables)，私有仓库。
- 本地启动与完整检查命令见仓库 README。

## 十分钟演示路径

1. 市级身份，在“项目管理”新增匿名项目，记录系统生成的项目编码，上传合同 PDF/JPG/PNG。
2. 在“导入中心”下载付款节点模板，填写项目编码、序号、金额、基准日期及账期；预览后提交有效行。也可直接新增付款节点。
3. 回到“应收管理”，点击“待确认”筛选，市级确认应收。
4. 切换该区县填报人，点击应收项目名称进入详情；登记一笔部分回款，可附到账凭证。
5. 在详情中“记录催缴”。正式函件必须附文件，普通联系可填写说明。
6. 切换本区管理员，在回款或催缴页面“作废并更正”，填写原因。查看原记录与替代记录同时保留。
7. 付清剩余款项。项目所有节点结清后进入“历史项目”；更正产生余额或新增节点时恢复进行中。
8. 使用“审计日志”搜索操作人或原因，展开查看完整原值与新值。在应收列表按区县、状态筛选并导出台账。

工作台四个指标均可点击进入相应明细。浏览器地址保留当前功能页，刷新和前进/后退可继续定位。

## 权限与处理规则

| 身份       | 数据范围 | 主要操作                                          |
| ---------- | -------- | ------------------------------------------------- |
| 市级管理员 | 全市     | 新建/导入项目、确认应收、风险设置、业务兜底       |
| 区县管理员 | 本区     | 新增节点、登记回款/催缴、作废更正、本区审计       |
| 区县填报人 | 本区     | 查看、登记回款/催缴、上传业务附件；不能确认或更正 |

区县范围、角色均在服务端验证。导入预览只能由创建该预览的会话在同一区县提交；切换身份或浏览器后请重新预览。

金额以“分”保存，应收付款日期按基准日加日历天计算。未确认应收不纳入已确认余额与催缴待办。作废流水不计入实收，作废催缴不作为法律风险基准。风险等级是流程提示，不是法律意见。

## 导入与异常处理

- 三份模板分别为项目主表 16 字段、付款节点 8 字段、回款流水 4 字段；不要改表头。每次最多 1000 行，Excel 文件最多 10MB，规范化内容过大时需拆分。
- 错误行不覆盖原数据；有效行在一次事务中提交。若写入中途失败，有效行、批次状态及审计全部回滚，可以修正后重新提交。
- 同一导入批次不能重复提交。回款导入以“应收、实收日期、金额、备注”识别重复；同一天同金额确属两笔到账时，应填写能区分的备注。
- 若其他人同时修改了余额或节点，提交可能返回冲突，请刷新并重新预览。提交时的服务端校验是最终依据，预览不是金额锁定。
- 手工回款网络超时后，先刷新流水核对是否成功，再决定是否重新登记；不要盲目连点。此版本没有跨网络重试的支付级幂等凭据。
- 附件限 PDF/JPG/PNG、单文件 10MB，并检查文件类型签名；不代表已完成病毒扫描或文档真实性鉴定。
- 加载失败会显示原因和重试按钮，不会自动清空数据。
- 审计页面展示当前范围最近 300 条，导入历史最近 50 批；更早数据保留在数据库中，尚未提供分页检索界面。

## 数据保存、备份与回退

本地与线上数据库彼此独立。默认本地状态在项目 `.wrangler/state` 下（D1 与 R2 都需保留）；若设置 `RECEIVABLES_STATE_PATH`，以该目录为准。源码、Excel 台账导出和构建包都不是完整数据库备份。

本地备份：先在运行服务的终端按 Ctrl+C 停止服务，再将完整状态目录压缩复制到项目外的专用备份目录，文件名带日期。保留 SQLite 相关文件及 R2 对象，勿只复制单个数据库文件。

恢复演练：在新的项目副本中恢复完整状态目录，使用同一版本源码启动，核对项目数、流水金额、审计和附件下载。不要直接覆盖正在使用的目录；先保留原状态备份。当前自动验收证明了正常服务重启后的数据与附件一致，未替代人为误删后的远端灾难恢复演练。

本次没有结构迁移，不重建或重置已有表。回退应用时先暂停写操作，选择上一已保存版本部署；不要通过删除财务记录“回退”业务。旧代码不包含本次竞争修复，回退后应继续暂停多人写入。

线上 D1/R2 由 Sites 托管，不在本地状态目录中。正式数据上线前，需由部署负责人确认并演练远端备份、恢复和权限方案。不要把数据库、会话、附件或访问凭据提交到 GitHub。

## 自动验收与限制

执行 `npm run verify`：类型检查、静态检查、日期/金额/风险/权限单测、真实 Excel 模板验证、完整 API 流程、竞争与回滚测试、三个 1000 行导入、重启持久化校验、生产构建。集成测试只操作专用临时目录；测试触发的故障不作用于日常演示或线上数据。

数据库写入采用 D1 事务批次，并在写入时重新校验金额和批次状态；依据 [Cloudflare D1 batch 文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。自动测试实际验证了失败回滚，而不只依赖设计假设。

本轮未做截图、浏览器交互式视觉验收、真实微信浏览器兼容、50 人负载测试或独立安全审计。界面已落实响应式布局、焦点提示、ARIA 状态、语义标签与 44px 移动按钮，但不宣称完整 WCAG 认证。

正式认证/单点登录、账号生命周期、真实客户数据迁移、外部 CRM/计费、AI 合同解析、交付模块和领导大屏仍不在一期范围。
