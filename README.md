# 项目应收管理系统（MVP）

面向市级管理员、区县管理员和区县填报人的中文内部管理工作台。本地开发时使用本地 D1/R2；发布到 OpenAI Sites 时由托管的 D1 保存业务数据，R2 保存合同、回款凭证和催缴函件。

交付说明、演示步骤、数据备份和已知边界见 [交付手册](docs/DELIVERY.md)。

私有访问：[项目应收管理系统](https://xian-receivables.yinxigao.chatgpt.site)（使用站点所有者的 ChatGPT 账号登录）。

## 已实现范围

- 应收工作台：待确认、剩余应收、部分回款、逾期未留痕等运营指标与明细。
- 项目管理：手工新增、合同附件、付款节点、详情与历史项目。
- 应收管理：待确认应收、市级确认、核销状态、逾期风险和法律风险。
- 回款流水：多笔回款、凭证、超额阻止、作废并追加更正。
- 催缴中心：微信、面谈、正式函件、领导介入、附件与不可覆盖时间线。
- 导入中心：三份 Excel 模板、预览、逐行校验、有效行提交和错误 CSV。
- 审计日志：实体、字段、原值、新值、原因、来源、操作人和操作时间。
- 风险设置：市级管理员调整阈值，规则变更写入审计。
- 服务端角色权限与区县数据隔离。
- 可点击的工作台指标、应收详情及合并时间线、按区县筛选与 CSV 台账导出。
- 回款、更正、核销与审计事务一致；导入预览绑定创建会话及区县，防止重复提交。

## 本地运行

前置条件：Node.js ≥ 22.13（验收使用 24.11.1）、pnpm；模板结构测试使用系统 `unzip`。首次取源码执行 `pnpm install --frozen-lockfile`。保留 pnpm 锁文件，不要混用其他安装器重建依赖。

依赖安装后：

```bash
npm run dev -- --host 127.0.0.1 --port 3000
```

这里使用 npm 执行已有脚本，避免某些 pnpm 版本在 `run` 前自动重装依赖；不会生成 npm 锁文件。

浏览器访问：`http://localhost:3000/`

首次访问会幂等创建数据库结构和匿名演示数据；再次启动不会覆盖已有业务数据。

接口集成测试会自动使用一次性的临时 D1/R2 状态目录和空闲端口，结束后清理临时状态，不会向日常演示数据库写入“自动化验收”数据。

## 演示身份

- 市级管理员：查看全市、创建项目、确认应收、调整风险规则及兜底处理。
- 区县管理员：查看本区、维护付款节点、登记及更正回款和催缴、查看本区审计。
- 区县填报人：查看本区、登记回款和催缴、上传附件。

页面右上角可切换角色和碑林、雁塔、莲湖三个匿名区县。HttpOnly Cookie 仅保存随机会话令牌，角色与区县从服务端会话读取；不接受客户端直接声明权限。这是可自由切换身份的演示机制，不等同于正式登录认证。

## 验证

```bash
npm run verify
```

该命令依次进行类型检查、静态检查、单元/真实模板测试、隔离接口测试、重启持久化验证和生产构建；任一步失败立即停止。也可单独运行 `npm run test:unit`、`npm run test:integration`、`npm run build`。

- 单元测试覆盖日期、金额、核销、逾期风险、法律风险、项目归档和权限矩阵。
- 接口测试覆盖跨区拒绝、完整链路、并发回款/更正、审计失败回滚、导入归属与重放、三类各 1000 行导入。
- 重启测试比对业务记录、会话及附件 SHA-256；只清理脚本自己创建的临时目录。
- `npm run db:generate` 应显示 11 张表且无未生成的结构变更。本次交付不修改数据库结构。
- 测试会主动制造两个数据库错误以验证事务回滚，相应 500 日志是预期结果；以最终测试汇总为准。

三份 `.xlsx` 模板已包含填写说明、冻结首行、日期/金额格式和 1000 行校验。可选维护脚本：`python3 scripts/prepare-templates.py`（需要 openpyxl；应用运行不需要 Python）。

## 一期边界

本 MVP 不包含正式账号或单点登录、交付模块、领导大屏、CRM/计费接口、AI 合同解析、历史数据迁移和公开网站级安全承诺。Sites 部署默认保持仅所有者可访问。
