# 健康检查与恢复

## 探针

| 路径                   | 成功                     | 失败含义                       | 用途                  |
| ---------------------- | ------------------------ | ------------------------------ | --------------------- |
| `/api/v1/health/live`  | HTTP 200，`status=live`  | 网关/API 进程或链路不可达      | 进程存活              |
| `/api/v1/health/ready` | HTTP 200，`status=ready` | 数据库结构或附件目录当前不可用 | 启动、接流量、Compose |
| `/api/v1/health`       | 与 ready 相同            | 兼容旧监控                     | 旧客户端过渡          |

匿名可访问健康接口是有意设计，只返回粗粒度状态。详细错误只写本机安全日志，不进入响应。

## 失败处理

1. readiness 失败时暂停业务写入，不通过删除 WAL、数据库、附件或凭据“修复”。
2. 查看本机 API/Gateway 日志和数据目录权限；不要把日志中的敏感内容发到公开渠道。
3. 需要恢复时先停止本项目进程，验证备份 manifest、SQLite integrity 与附件 checksum。
4. 恢复到新的空目录，以 `RECEIVABLES_DATA_DIR` 指向新目录验证；不覆盖原目录。
5. 旧构建只能搭配其兼容 Schema；未来迁移后优先前向修复，回退按 ADR 和切换记录执行。

临时 Cloudflare Tunnel 在线不等于源站 ready。长期运行应使用固定受管 Tunnel 并结合其健康/指标能力；当前临时域名仍不构成 SLA。
